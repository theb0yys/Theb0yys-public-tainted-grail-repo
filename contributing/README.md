# Contributing Documentation

Use this section when you are adding, correcting, or reorganising documentation in this repository.

The aim is simple: make the repository more useful to someone building or debugging a FoA mod **without weakening the technical evidence behind the information**.

## Before adding a new page

Ask:

- Is this teaching someone how to do a task? Put it in **Guides**.
- Is this explaining how FoA itself works? Put it in **Knowledge / Systems**.
- Is this a known reusable modding technique? Put it in **Knowledge / Mechanics**.
- Is this an exact lookup such as a type, hook, GUID, service, or version fact? Put it in **Knowledge / Reference**.
- Is the answer still being investigated? Keep it in **Research**.
- Is it a small runnable code example? Put it in **Examples**.
- Is it a project someone is meant to copy and adapt? Put it in **Templates**.

Do not create a second competing explanation of an existing technical claim just because another page needs to mention it. Link to the maintained explanation instead.

## Writing style

Write for the modder using the page.

The opening should explain:

1. what the page helps them do or understand;
2. when they would use it;
3. what important distinction or risk they should know before acting.

Keep exact technical names, evidence limits, version scope, and validation state intact when polishing prose.

See [Document archetypes](authoring/document-archetypes.md) for the different page shapes used by the repository.

General contribution and public-repository rules are in [CONTRIBUTING.md](../CONTRIBUTING.md).
