# Set Up Windows for Tainted Grail Modding

## What you're doing

You are preparing a clean Windows workspace for either runtime plug-in development or Merlin Workshop content authoring.

The setup and examples in this repository are currently Windows-focused.

## What you need

For either path:

- **Tainted Grail: The Fall of Avalon** installed locally;
- this repository available on your machine;
- a modding workspace outside the game installation.

For runtime plug-ins:

- the correct BepInEx lane installed and able to start;
- **Visual Studio 2022 Community** or another editor/build environment capable of building the supplied C# projects.

For Merlin Workshop content authoring:

- Unity Hub;
- a Merlin Workshop release archive or a proper Git checkout/fork.

## What you'll learn

By the end of this page, you will know:

- where to keep your modding workspace;
- which Windows/.NET tooling the supplied plug-in starters expect;
- how to get this repository;
- how to keep the starter, toolkit, mods, and game installation separate.

## Steps

### 1. Prepare the runtime plug-in tools

Open **Visual Studio Installer**.

Select your Visual Studio installation -> **Modify**.

Install the **.NET desktop development** workload.

For the Mono template, also make sure the **.NET Framework 4.7.2 targeting pack/developer pack** is available.

The IL2CPP starter targets net6.0; the Mono starter targets net472.

### 2. Get this repository

If you do not use Git yet:

1. Open the repository page on GitHub.
2. Click **Code**.
3. Choose **Download ZIP**.
4. Extract it somewhere outside the game folder, for example:

~~~text
C:\TGModding\community-starter
~~~

If you already use Git, clone normally instead.

### 3. Prepare the content-authoring tools

For the Merlin Workshop content pipeline, the inspected project currently reports:

~~~text
Unity Editor 6000.0.60f1
~~~

Merlin Workshop's own README explicitly says **do not use GitHub's autogenerated ZIP for the toolkit**. Use its release archive or a proper Git checkout/fork.

A clear beginner workspace is:

~~~text
C:\TGModding\
  community-starter\
  merlin-workshop\
  MyMods\
~~~

Keep these separate from the game installation.

## What success looks like

Before continuing, you should have:

- the game installed;
- a normal modding workspace outside the game;
- the starter repository available locally;
- your code editor/build tools installed;
- for runtime plug-ins, BepInEx already able to start;
- for content authoring, the correct Merlin Workshop project available separately.

## Common problems

**BepInEx does not start:** fix the loader setup before adding your own plug-in to the problem.

**Mono build reports missing reference assemblies:** install the .NET Framework 4.7.2 targeting/developer pack.

**Merlin Workshop was downloaded with GitHub's autogenerated ZIP:** use the toolkit's documented release archive or a proper Git checkout/fork instead.

**Your source is inside the game directory:** move your modding workspace out of the game installation so source, build output, and game files stay separate.
