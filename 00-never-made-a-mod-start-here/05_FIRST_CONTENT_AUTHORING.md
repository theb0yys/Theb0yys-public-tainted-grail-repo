# Make Your First Piece of Content

## What you're doing

You are opening the Merlin Workshop authoring environment and creating a minimal mod-owned item definition before moving into weapons, armour, or creatures/NPCs.

## What you need

- Merlin Workshop from its release archive or a proper Git checkout/fork;
- Unity Hub;
- the Unity editor version documented by the toolkit snapshot you are using;
- a separate modding workspace;
- your own legally redistributable visual material if you choose to add visuals.

For the inspected snapshot, the project reports:

~~~text
Unity Editor 6000.0.60f1
~~~

## What you'll learn

You will learn how to:

- open Merlin Workshop cleanly;
- create a basic `ItemTemplate`;
- give content a mod-owned identity;
- configure only the minimum fields first;
- distinguish source-confirmed authoring structure from runtime proof.

## Steps

### 1. Get Merlin Workshop correctly

The inspected Merlin Workshop README says not to use GitHub's autogenerated ZIP for the toolkit.

Use either:

- the toolkit's release archive; or
- a proper Git checkout/fork.

Install/open the editor version documented for the toolkit release or snapshot you selected.

### 2. Open the project

In Unity Hub:

1. choose **Add / Open project from disk**;
2. select the Merlin Workshop project directory;
3. allow Unity to import/compile;
4. do not start changing content while the project is still importing or showing compile errors.

Your first goal is a clean editor state.

### 3. Start with an item

For a first content test, prefer an item before a custom creature.

The inspected Merlin authoring route exposes:

~~~text
Assets -> TG Data -> Miscellaneous -> Item
~~~

Use that route to create a new `ItemTemplate` prefab.

Give the test item a unique mod-owned identity/name.

Do not copy a vanilla/game icon or model just to make the test look complete. Use your own legally redistributable source material or leave optional visual polish for later.

### 4. Configure the minimum

For the first item, focus on:

- correct template/inheritance family;
- name/localization;
- icon only if you have a mod-owned icon;
- basic price/weight/stack behaviour only as needed.

Do not add every attachment at once.

Save the asset.

### 5. Specialize only after the base item makes sense

Once the base item workflow makes sense:

- weapon: [docs/pipelines/WEAPONS.md](../docs/pipelines/WEAPONS.md)
- armour: [docs/pipelines/ARMOUR.md](../docs/pipelines/ARMOUR.md)
- creature/NPC: [docs/pipelines/CREATURES_KANDRA.md](../docs/pipelines/CREATURES_KANDRA.md)

Weapons and armour are specialized item pipelines.

Creatures are a larger pipeline involving visual preparation plus NPC spec/template/fighting-style wiring.

### 6. Record the evidence you actually produced

The current public pipeline documents identify the authoring structure from inspected Merlin source as **STATIC_CONFIRMED**.

A fresh end-to-end editor/game run was **NOT_RUN** during that documentation pass unless a document explicitly says otherwise.

For your own successful content test, record:

- Merlin/toolkit commit or release;
- Unity editor version;
- game build;
- what exact definition you created;
- what you actually observed in editor/game.

## What success looks like

Your first content-authoring session passes when you can:

- open the expected toolkit/editor cleanly;
- create a mod-owned item definition through the documented route;
- save it without project errors;
- explain its template/category relationship;
- repeat the edit/save cycle;
- state clearly whether you have editor evidence, game-runtime evidence, or both.

## Common problems

**Unity is still importing or has compile errors:** do not start authoring until the project reaches a clean state.

**You used GitHub's autogenerated ZIP for Merlin Workshop:** use the toolkit's supported release archive or a proper Git checkout/fork.

**You begin with a creature:** creatures add Animator, Kandra renderer/rig, collider/ragdoll, NPC spec, fighting-style, animation, spawn, combat, and other variables. Learn the base content loop first.

**You use extracted game assets to make the test look complete:** keep the public/mod-owned content redistributable.
